# 图片处理方式对比

## 1. 纯前端本地处理

文件从用户设备直接进入浏览器，由 Canvas、Blob、Web Worker 等能力完成处理，结果也直接下载到用户设备。

优点：

- 图片不经过我们的服务器，隐私解释更简单。
- 不需要文件存储、上传接口、数据库和后端服务器。
- 流量成本和基础设施成本低，适合广告收入尚未稳定的阶段。
- 可以部署成静态网站，发布和回滚简单。
- 用户不必注册账号。

限制：

- 受用户设备内存、浏览器能力和手机性能影响。
- 超大图片或批量任务可能处理较慢或失败。
- HEIC、RAW 等格式的兼容性需要额外方案。
- 不能天然提供跨设备历史记录、云端保存和分享链接。
- 复杂算法通常需要下载更大的前端处理包。

## 2. 后端上传处理

文件先上传到服务器或对象存储，再由后端服务、任务队列或云函数完成处理，最后返回下载结果。

优点：

- 可以使用更强的 CPU、内存和专业图像处理库。
- 更适合超大文件、复杂格式和长时间任务。
- 可以实现云端保存、跨设备访问、分享链接、账号历史和 API。
- 处理能力和结果更容易统一，不依赖用户设备性能。

代价：

- 需要上传接口、存储、任务处理、清理策略、限流和监控。
- 图片带宽、存储和计算会产生持续成本；流量增长时成本也会增长。
- 需要更严格的隐私、安全和合规设计，包括加密、访问控制、自动删除和异常文件防护。
- 用户需要等待上传，弱网和移动网络下体验更差。
- 账号、权限、失败重试和任务状态会显著增加开发范围。

## 3. 对 FileTools 的建议

MVP 采用纯前端本地处理，理由是：核心功能足够、上线速度快、隐私卖点清晰、广告模式早期无需承担文件处理成本。代码应把“校验、处理、下载”封装成可替换服务接口，未来可以增加混合模式：小文件本地处理，超大文件在用户明确同意后上传处理。

在确认采用该方案前，需要接受三个产品规则：图片不会在云端保存、关闭或刷新页面可能丢失当前任务、超大文件会有明确的浏览器限制。
