# 产品需求文档（PRD）

## 1. 用户与场景

### 目标用户

- 需要快速处理图片的普通用户。
- 需要上传图片到网站、表单或社交平台的内容创作者。
- 希望避免安装软件、注册账号或上传敏感图片的用户。

### 核心场景

“我有一张或多张图片，需要压缩、转换格式或调整尺寸，并马上下载结果。”

## 2. MVP 功能范围

### P0：必须有

1. 拖拽上传和文件选择。
2. 支持 JPG、PNG、WebP 输入。
3. JPG、PNG、WebP 输出格式选择。
4. 图片质量调整。
5. 宽高调整，并保持比例开关。
6. 单张处理和批量处理。
7. 处理进度、成功、失败和重试反馈。
8. 单张下载和批量 ZIP 下载。
9. 清除文件、重新开始。
10. 本地处理提示、隐私说明和浏览器兼容提示。
11. 简体中文/英文切换，记忆用户选择。
12. 浅色/深色模式切换，并支持跟随系统主题。
13. 文件工具箱目录，提供图片、PDF、DOCX 和 PPTX 工具入口。
14. PDF 合并、PDF 拆分、图片转 PDF。
15. DOCX 转 HTML/文本。
16. 图片生成 PPTX。

### P1：首发后补充

- HEIC/AVIF 支持探测与兼容提示。
- 常用社交媒体尺寸预设。
- 最近一次参数保存在本地浏览器。
- 离线 PWA 缓存。
- PDF 转图片预览。
- Markdown/纯文本转 DOCX。
- PDF、Word、PPT 高保真双向转换（需要独立转换引擎）。

### P2：暂不排期

- PDF 工具集合。
- 云端链接分享。
- 用户账号和历史记录。
- AI 背景移除或增强。

## 3. 页面范围

- `/`：工具箱首页，展示所有可用工具和隐私原则。
- `/image-tools`：核心图片处理工作区。
- `/compress-image`：图片压缩 SEO 落地页。
- `/convert-image`：格式转换 SEO 落地页。
- `/resize-image`：尺寸调整 SEO 落地页。
- `/about`：产品说明、隐私承诺和联系方式。
- `/privacy`：隐私政策。
- `/terms`：使用条款。
- `/faq`：常见问题。
- `/:pathMatch(.*)*`：404 页面。

每个工具页都必须有独立、原创且能解决用户问题的说明内容，不能只复制同一段 SEO 文案。

页面必须支持中英文文案、页面标题、描述、FAQ 和错误信息切换；语言切换不应改变当前已选择的文件和处理参数。

## 4. 用户故事与验收标准

### 上传与处理

作为用户，我可以选择或拖入图片，以便开始处理。

- 只接受允许的图片格式；不支持的文件显示原因和处理建议。
- 大文件或超出数量限制时，在处理前明确提示。
- 处理期间按钮有禁用和进度状态，用户不会误以为没有响应。

### 参数设置

作为用户，我可以调整输出格式、质量、尺寸和比例，以便获得符合目标场景的文件。

- 所有字段有可见标签，不依赖 placeholder 说明。
- 修改参数不会丢失已选文件。
- 保持比例开启时，修改宽度会正确计算高度。

### 下载结果

作为用户，我可以预览结果信息并下载，以便继续使用文件。

- 显示原始大小、处理后大小和压缩比例。
- 成功项可单独下载；批量结果可下载 ZIP。
- 某一文件失败不应阻塞其他文件完成。

### 隐私与广告

作为用户，我能理解图片是否上传、广告与工具的边界。

- 上传区域附近明确写出“在浏览器本地处理，不上传图片”（若实际实现符合该承诺）。
- 广告位有明确广告标识，并与操作按钮保持足够间距。
- 不使用诱导点击、伪装成下载按钮或遮挡核心操作的广告布局。

## 5. 产品规则

- 默认不要求登录。
- 默认不保存用户文件。
- 单文件大小、批量数量和像素上限必须是可配置常量，并在 UI 中说明。
- 所有失败状态必须包含原因和恢复动作。
- 核心工具每个页面只有一个主要 CTA：选择图片/开始处理/下载结果中的当前主要动作。
