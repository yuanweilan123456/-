# 软件需求规格说明（SRS）

## 1. 功能需求

### FR-01 文件输入

系统应支持文件选择、拖拽和移动端拍照/文件选择入口。系统应校验 MIME 类型、扩展名、文件大小和数量。

### FR-02 图片解码

系统应读取图片元信息并在浏览器端解码。解码失败时应提示文件可能损坏或浏览器不支持该格式。

### FR-03 图片处理

系统应支持格式转换、质量调整、尺寸调整和保持比例。处理任务应在 Web Worker 或等效的非阻塞机制中运行，避免大图处理冻结界面。

### FR-04 结果管理

系统应为每个输入文件维护 pending、processing、success、error 状态，并允许单项重试、单项下载和批量下载。

### FR-05 错误恢复

系统应区分格式不支持、文件过大、解码失败、处理失败、内存不足和下载失败，并为每类错误提供用户可执行的恢复动作。

### FR-06 内容与 SEO

系统应输出可被搜索引擎理解的页面标题、描述、规范链接、站点地图和 robots 配置。工具页应包含结构清晰的说明、FAQ 和内部链接。

### FR-07 广告位

系统应提供不影响核心流程的广告容器，异步加载第三方脚本，并为脚本未加载、审核未通过或用户选择不接收个性化广告时提供稳定布局。

## 2. 非功能需求

### 性能

- 首屏工具界面不应等待广告脚本才能交互。
- 图片处理不应阻塞主线程。
- 为异步广告和图片预览预留尺寸，避免明显布局跳动。
- 处理完成后及时释放 Blob、Canvas 和 Worker 资源。

### 可访问性

- 键盘可完成选择、设置和下载操作。
- 所有表单控件有可见标签和错误说明。
- 焦点状态清晰，状态变化使用 aria-live 通知。
- 正文对比度达到 WCAG AA，不能仅靠颜色表达状态。
- 交互区域不小于 44×44px，并支持减少动态效果设置。

### 兼容性

首期验证最新版 Chrome、Edge、Safari、Firefox，以及 iOS Safari 和 Android Chrome。对不支持的浏览器能力提供降级提示。

### 安全与隐私

- 不把用户图片发送到自有服务器。
- 不记录图片内容、文件名中的敏感信息或图片元数据，除非产品后续明确改变规则并更新隐私政策。
- 第三方广告和分析脚本必须按适用地区的同意机制加载。
- 部署启用 HTTPS、内容安全策略和安全响应头。
